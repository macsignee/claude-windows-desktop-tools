# 設計の記録 (`docs/design/<画面>.md`) の書式と書き方

`ui-test-first` の SKILL.md の手順 1 (計画の承認のあと) から、読む。

**承認されたら、設計を `docs/design/<画面>.md` に保存する** (計画の「触るファイル」に含めて示す。フォルダがなければ作る。UTF-8、BOM なし、LF。すでにあれば、変わった行だけを直し、末尾の「変更履歴」に 1 行足す)。

```markdown
# <画面名> の設計

- 日付: YYYY-MM-DD   - 仕様書: docs/specs/<名前>.md (あれば)   - フレームワーク: WinForms | WPF | MFC   - 種類: メイン | モーダルなダイアログ | モードレスなウィンドウ

## 選んだ案
(スケッチなどの画像があれば、「スケッチ: docs/design/images/<画面>-sketch.<拡張子>」と、1 行書く。`references/sketch.md`)
(1〜3 行。配置の図があれば、そのまま)

## 開き方と閉じ方 (メインウィンドウ以外のときだけ)
| 項目 | 内容 |
|---|---|
| 開く部品 | メインウィンドウの、どのボタン・メニュー (識別の名前) |
| 閉じ方と結果 | OK / Cancel / ×。メイン側で変わること。戻り値 |
| 開くときの前提 | メインの、どの状態が要るか |

## 依存する Model (Fake を使うときだけ)
| Model (インターフェース) | 実装 (Fake / 本物) | 契約テスト | 状態 (Fake のみ / 本物あり / 結合済み) |
|---|---|---|---|

## 部品
| 部品 | 種類 | 識別の名前 | 守る規則 ID |
|---|---|---|---|

## 操作と期待
| # | 操作 | 期待 | 確認場所 | 守る規則 ID |
|---|---|---|---|---|

## 選ばなかった案と理由
(案を比べたときだけ。なければ、「なし」)

## 変更履歴
- YYYY-MM-DD: 作成
```
- **この記録は、設計の正本**。UI テストの名前 (`画面_条件_期待`) と、「操作と期待」の `#` を、対応させる。画面を変えるときは、先にここを直す。
- **コードから、推測して書かない** (計画で、承認された内容だけ)。画面を作ったあとで、部品の名前が変わったら、記録を、実際に合わせる。
