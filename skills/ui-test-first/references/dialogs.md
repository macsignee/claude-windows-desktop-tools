# ダイアログ・サブウィンドウの設計とテスト

`ui-test-first` の SKILL.md の手順 1 で、**メインウィンドウではない画面** (モーダルなダイアログ、モードレスなサブウィンドウ) を頼まれたときに、**先に**読む。

## 計画に足す 4 つ (手順 1)

- **画面の種類 (メインウィンドウか、ダイアログ・サブウィンドウか):** **メインウィンドウではない画面 (モーダルなダイアログ、モードレスなサブウィンドウ) の計画には、次の 4 つを、表 (項目 / 内容) にして足す。** (1) **種類:** モーダル / モードレス。(2) **開き方:** メインウィンドウの、どのボタン・メニュー (識別の名前) で開くか。**UI テストは、メインウィンドウから、そこを押して、開く** (ダイアログだけを、直接、開く道具は、WPF / WinForms にはない。**開くボタンも、部品として、計画に含め、メイン側の View に、名前つきで、足す**。MFC の DLL に、呼び出す exe がないときは、前提の画面ホスト (`add_ui_host.py`) が、その画面を、そのまま開く)。(3) **閉じ方と結果:** OK / Cancel / ×。閉じたあとに、メイン側で変わること。戻り値。(4) **開くときの前提:** メインの、どの状態が要るか。UI テストで作りにくいときは、**規則・ViewModel / Presenter の単体テストで、確かめる範囲を広げる** (UI テストは、開く・閉じる・主要な流れに、絞る)。

## ダイアログのデータと規則の置き場所 (計画に 1 行足す)
- **ダイアログが扱うデータ:** 計画に、「データのクラス名 / 置き場所 (基本は、ロジック層) / 持たせる規則 (入力の検査・表示用の派生値)」を、**1 行**足す。**ダイアログ専用の Presenter / ViewModel は、増やさない** (複雑になったときに、足す)。
- **WinForms:** データのクラスは、Presenter と同じ層に、別のファイルで置き、Presenter (またはダイアログのサービス) が、渡して、結果を受け取る。**MFC:** ダイアログのコンストラクターの引数で受け取り、`DoDataExchange` で出し入れする。規則は、データのクラス (ロジック層) に置き、**単体テスト (MSTest / GoogleTest) で、確かめる。** UI テストは、ダイアログごとに、煙テスト 1 件。 **ダイアログは、確定 (OK) するまで、渡されたデータを変更しない。** 入力中の検査は、一時的なデータ (または生の文字列) で行い、OK のときに、書き戻す (キャンセル・× では、渡されたデータが、そのまま残る)。
- Model (リポジトリ) ではない。Fake・契約テスト・「依存する Model」の表の対象外 (`references/model-switching.md` の冒頭)。

## テストの書き方 (手順 2)

- **ダイアログ・サブウィンドウの中の部品は、`Find(window, "Id")` で探す。** `var dlg = OpenModal(Find("EditButton")); var ok = Find(dlg, "OkButton"); UiDialogs.Click(ok); Assert.IsTrue(WaitModalClosed());` の形 (`Find("Id")` は、メインウィンドウの中だけ。`Find(window, "Id")` は、同じ探し直し (5 秒)・操作の記録・プレゼンの赤い枠が、働く)。モードレスは、`WaitWindow(title)` が返す window を渡す。ダイアログの外観は、`Snap("名前", dlg)` で撮る。
- **入力と閉じ方は、遅い書き方を避ける (別のデスクトップの実測):** 入力欄は `UiDialogs.SetText(Find(dlg, "EditNameTextBox"), "次郎")` (`.AsTextBox().Text =` は、1 回に約 2 秒)。ボタンは `UiDialogs.Click`。**× で閉じるテストは `UiDialogs.CloseWindow(dlg)` のあと `WaitModalClosed()`** (`dlg.Close()` は、約 4 秒)。既存のサンプルのテストが、古い書き方でも、まねをしない。
