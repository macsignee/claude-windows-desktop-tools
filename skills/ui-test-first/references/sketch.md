# スケッチ・画像からの入力 (手書き、ドローツールの図、画面の写真)

`ui-test-first` の SKILL.md の手順 1 で、**ユーザーが、画面・ダイアログ・フォームの画像 (手書きのスケッチ、ドローツールの図、既存の画面の写真) を渡したとき**に、**先に**読む。画像は、**部品の構成と並び**を決める入力にする。動作や識別の名前は、画像から決まらないので、**確認してから、計画にする**。

## 手順

1. **画像を読む。** `Read` ツールで、画像として開く (複数あれば、1 枚ずつ)。読み取る対象は、部品の種類 (ボタン・入力欄・ラベル・リスト・コンボ・チェックなど)、並び (上下・左右・グループ)、タイトル・文言、手書きの注記 (識別の名前・動作のメモ)。
2. **読み取りの結果を、表にして、見せる。** 列は、「部品 / 種類 (推定) / 画像上の文言 / 位置 / 確信 (高・中・低)」。**読み取れなかった文字や、種類が曖昧な部品は、確信を「低」にして、推測で埋めない。**
3. **画像から決まらないことを、一覧にして、確認する** (推測で、決めない)。
   - **識別の名前** (AutomationId・コントロール ID): 画像に書いていなければ、案を出す。
   - **動作:** 押したときの結果、有効・無効の条件、入力の検査。
   - **画面の種類:** メイン / モーダル / モードレス。フレームワーク (WinForms / WPF / MFC) も、不明なら聞く。
   - **データ:** 入力値、共有するデータ (モードレスは、すぐ反映する。`references/dialogs.md`)。
   - **曖昧な箇所:** 手順 2 で、確信が「低」だった部品。
4. **計画にする。** 確認した内容を、SKILL.md の手順 1 の書式 (種類、開き方・閉じ方、部品の表、操作と期待、ダイアログのデータと規則) にして、承認を得る。**並び (レイアウト) は、計画の「選んだ案」に、部品の一覧と、簡単な配置の図 (文字) で書く。図は、スケッチの配置を、そのまま写す** (たとえば、ラベルが入力欄の上なら、上に描く。標準的な配置に、勝手に直して描かない)。**標準の部品やガイドライン (`ui-design-review`)、既存の画面との統一に合わせて、スケッチと変える点があれば、計画に、「スケッチと違う点」の表 (点 / スケッチ / 計画 / 理由) として、書く。なければ、「スケッチと違う点: なし」と書く。** ユーザーは、承認のときに、ここを確かめる (実機で、図とスケッチが違うのに、気づかれずに、承認された例がある)。
5. **画像を、設計の記録と同じ場所に、保存する。** `docs/design/images/<画面>-sketch.<拡張子>` (フォルダがなければ作る。ユーザーのファイルが、プロジェクトの外にあれば、**コピー**する。元のファイルは、動かさない)。設計の記録 (`docs/design/<画面>.md`) の「選んだ案」に、「スケッチ: docs/design/images/<画面>-sketch.<拡張子>」と、1 行書く。すでにあるファイルは、上書きしない (番号を付ける)。
6. **実装は、既存の流れのとおり** (テスト先行。Red → Green)。**UI テストは、構造と動作を確かめる** (見た目・レイアウト・色は、対象外)。

## 見比べ (ユーザーが頼んだときだけ)
ユーザーが、「スケッチと見比べて」と頼んだときだけ行う (毎回は、しない)。**頼まれていない報告 (プレビューの実行結果など) では、「スケッチのとおり」「スケッチに沿っている」と、書かない** (見比べていないため。画面の事実 (何が、どこに、表示されているか) だけを書く)。プレビュー (`Snap`。`references/preview.md`) の PNG と、保存したスケッチを、`Read` で並べて見て、**ずれを一覧にして、報告する** (並び・グループ・文言・欠けている部品・余分な部品)。**直すかどうかは、ユーザーが決める。** 勝手に、直さない。

## 限界 (先に、伝える)
- **ピクセルの一致は、目的ではない。** 標準の部品で、UI デザインガイドライン (`ui-design-review`) に沿う配置にする。色・フォント・正確な寸法は、スケッチと、同じにならない。
- **画像から決まるのは、構造 (何が、どこに、どう並ぶか)。** 動作は、確認が要る。
- **手書きの文字の読み取りは、誤ることがある。** 手順 2 で、必ず、結果を見せる。
- **画像に、個人情報や、社外秘の内容が写っていないかを、保存の前に、確かめる** (設計の記録は、リポジトリに入る)。写っていれば、保存せず、ユーザーに聞く。
