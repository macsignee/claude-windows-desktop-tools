## 2. 決定済み (蒸し返さない)
- **外のソースに対する静的チェック (`mfc-check` など) は、しない** (ユーザーの決定、2026-11-26)。**モジュールをまたぐ切り分けは、デバッグ (`vs-debug`) 経由。** 境界の静的な検査 (ビルド設定の食い違い、ヘッダーのずれ、CRT をまたぐ型) は、将来の話。
- 背景: 別のソリューションでビルドしたライブラリ (静的ライブラリ・DLL・アセンブリ) が、日次で共有フォルダに配布される。利用側は、番号を見ず、バッチで引く。ソースは、参照できる場所にあるが、プロジェクトの設定は、ソースの場所を持たない。
- **所有者の判定の原則:** 分からないものは `unknown`。**誤って `ours` / `ext` と言わない** (目的は、外のライブラリの不具合を、こちらのバグと誤認させないこと)。印と要約は、**ヒントであり、断定ではない** (こちらが誤った引数を渡して、外の中で落ちるときも `OWNER: top=ext`)。判定は、**ソースのパスを先に見る** (静的ライブラリは、exe に取り込まれ、モジュールが、こちらの exe になるため)。`ours` は、こちらのソースが見えるときだけ。
- **UI テストのアタッチモード:** きっかけの操作は、**UI に触れずに終わる**形 (止まったアプリは、UIA に応答しない)。きっかけ専用のテスト (`[TestCategory("DebugTrigger")]`) を、必要なときに書く。デスクトップは、ユーザーのもの (`desktop=visible` 固定)。
- **マージは、ユーザーが行う。push と PR は、ユーザーが明示的に頼んだときだけ** (頼まれていないのに、まとめて実行すると、権限で拒否される)。
