## 3. 画面モデルの設計 (決定事項の要約。詳細は `docs/UI-MODEL-GUIDE.md`)
- **画面モデルは、すべての画面・ダイアログで必須。唯一の例外は、MFC の SDI・MDI のメインのビュー (`CView` 派生。2026-11-17 に明記)。** SDI・MDI のアプリでも、ダイアログ・`CFormView`・画面 DLL (`ui-host`) は、画面モデルで作る。業務の規則は、View・Document に書かず、ロジック層に置く。Document/View への適用は、実アプリで必要になったときに設計する。
- WPF は `ViewModel` (`ViewModelBase`、`Validate()`、`ErrorTexts[欄名]`)、WinForms / MFC は `<画面名>ScreenModel`。Presenter は、WinForms で任意 (WinForms の型がないと書けないものだけ)。
- 契約: 状態、操作 + `CanXxx`、`Validate()` / `IsValid` (純粋)、変更通知、`Commit()` (bool) + `Failure` (文章)、`Cancel()`。C# は .NET 標準の `ValidationResult`、共通部品は `RepositoryException` だけ。C++ は `ValidationError`、`Observable`、`std::wstring`、`ToCString` / `ToWString`。
- **文言:** 画面モデルが日本語で作り、画面ごとに 1 か所 (`MainMessages` など)。リソースへの移行は、必要になったとき。
- **シナリオの切り替え:** Fake の画面モデルのクラスは、ひな形に置かない。本物の画面モデルに、Debug のときだけ、シナリオの初期状態を当てる (`APP_FAKE_SCREENS`、`[FakeScreen("Main", "InvalidName")]`)。
- **ひな形に入れない、と決めたもの (2026-11-17):** Fake リポジトリの `FailNext` / `FailWhen` と `APP_MODEL=fake:<シナリオ>`、画面モデルとリポジトリの契約テストの生成。**理由:** サンプルにリポジトリがなく、画面モデルの実装が本物の 1 つだけ。リポジトリを持つ画面や、つなぎの Fake を作るときに、`csharp-test-first` / `cpp-test-first` の `CONTRACT-TESTS.md` の書き方に沿って書く。
- **旧 Presenter 構成:** 移さなくてよい (「WinForms (MVP)」の表記は通用する)。移すときは、`docs/MIGRATION-SCREEN-MODEL.md` (WinForms は 9 手順。WPF・MFC は、生成物の差分から書いた短い節で、実際の旧ソリューションでは未確認)。
