## 4. 現在の仕組みの要点 (ハーネスの全体像)

- Windows のウォッチャー (`host-tools/watch_and_build.ps1`) が、ソリューションのフォルダの `trigger_*.flag` を 1 秒周期で監視。WSL の Skill のスクリプト (`*_once.sh`) が、フラグを置き、結果のマーカー (`*_result.txt`) と `run_id.txt` を待つ。
- フラグ: `trigger_build.flag` / `trigger_test.flag` (ビルド + テスト) / `trigger_uitest.flag` / `trigger_gtest.flag` / `trigger_package.flag`。
- 結果の値と終了コード: `OK` / `PASSED` 0、`FAILED` 1、`BAD_ARGS` 2、`WATCHER_NOT_RUNNING` 3、`ENV_ERROR` 4、`TIMEOUT` 5、`BUILD_FAILED` 6 など。
- スクリプトは、実行の初めに古い結果を消し、フラグに実行 ID を書き、ID の一致するマーカーだけを受け取る。ウォッチャーが処理中なら、`WATCHER_NOT_RUNNING` と誤報しない。
- Skill: `new-solution`、`add-package`、`auto-build`、`build-test-loop`、`cpp-test-first`、`wpf-test-first`、`ui-test-first`、`add-feature`、`winforms-check`、`wpf-check`、`mfc-check`。

## 6. ハーネスの再検討の論点 (今回の作業で見えた、摩擦のあった点)

これは、実際に起きたことからの見立て。決定ではない。

1. **古い結果の取り違えが、繰り返し起きた。** 対策 (結果の消去、実行 ID、更新時刻の確認) を足してきたが、確認の手順側 (人間と Claude の双方) でも、取り違えた (17:58 の古い結果を、手で置いたフラグの結果と誤認)。結果に、自己記述 (いつ、どの実行の、どの入力の結果か) を持たせる方法がある。
2. **実機の確認の往復が重い。** ホスト側は PowerShell で、WSL からは動かせない。疑似ウォッチャーで、分岐は検証できるが、ウォッチャー本体の挙動は検証できない。確認の依頼文の作成と、結果の読み取りに時間がかかる。
3. **反映の手順が分かれている。** `install.sh` (Skill / 規約)、`c:\Tools\cpp-watcher` へのコピー (ホスト側)、ウォッチャーの再起動。どれかを忘れると、古い版で確認してしまう。版の表示 (ウォッチャーの起動バナーに版) と、版の不一致の検出が、ない。
4. **フラグのプロトコルの互換性。** 新しい Skill と古いウォッチャー、古い Skill と新しいウォッチャーの組み合わせを、コメント行などで保っている。この設計の制約が、実装を複雑にしている。
5. **テストの時間。** 疑似ウォッチャーのテストは、待機 (15 秒の回収待ちなど) を含み、全体で数分。`CLAUDE_PICKUP_WAIT` で短縮できるものと、できないものが混在している。
6. **環境変数の漏れ** (`GTEST_FILTER`、`Platform`)。子プロセスへの継承の管理が、場当たり的になりやすい。
7. **記録の肥大。** 記憶のファイルや DESIGN の節が、1 行に長く書き込まれて読みにくい。
8. **サンドボックスの制約** (`rm -rf`、push / fetch、書き込みの許可が大文字小文字を区別、Claude の設定フォルダへの書き込み)。依頼文を、コンソールの Claude に渡す運用が、前提になっている。

## 7. 作業の教訓 (再発防止)

- Python の `str.replace` による置換には、必ず `assert s.count(a)==1` を付ける (黙って空振りした)。
- `.ps1` は UTF-8 (BOM 付き) + CRLF。Python で読み書きすると LF になる → `host_tools_static_test.sh` の「UTF-8 BOM + CRLF」が検出する。バイナリで扱う。
- ユーザーが貼る報告は、古い、または途中で切れていることがある。ファイルの更新時刻と配置先の内容を、確かめる。
- ステップが例外を飲む作りは、全滅でも合格に見える (`OK=0` は落とす)。
- 確認の依頼で、順序を誤解されやすい操作 (例: 「実行の前に消す」) は、手順を分けて書く。
